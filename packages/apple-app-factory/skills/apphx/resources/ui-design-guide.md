# ui-design-guide.md

> 这是给 apphx 内置 `ui-designer` 角色的设计指南。宿主若配置了本地 UI 设计类 skill，可结合使用，但 apphx 不依赖宿主特有 skill。无设计稿时，`ui-designer` 必须依据本指南产出 `docs/ui-design.md`；`developer` 必须与 `architecture.md` 和 `docs/ui-design.md` 保持一致。

## 0. 目标与边界

- 先解决「只说需求、没有设计稿时 UI 质量差」：用令牌与逐屏规范替代自由发挥。
- 原则：简洁、克制、一致。禁止样板化的「模板感」设计——颜色、圆角、阴影和布局必须是本产品的真实设计决策，而不是从模板库照搬的装饰。
- 有设计稿（`designRef`）时，忠实还原设计稿，不自行增删视觉决策；无法访问设计稿时如实记录并降级到本指南，绝不虚构设计来源。

## 1. 设计令牌模板

在 `docs/ui-design.md` 中落成一份可执行令牌表，实现层按名引用，禁止散落的魔法值。

### 1.1 色板与语义色

- `primary`：主色（品牌/主操作），并给出主色上的文本前景色。
- `neutral`：中性色阶（`neutral-0` 背景 … `neutral-900` 文本），至少给出背景、卡片、边框、文本四档。
- 语义色：`success`、`warning`、`danger`，每色同时给出深色/浅色背景与前景文本。

对比度要求（正文与背景）：

- 常规正文 ≥ 4.5:1（WCAG AA）。
- 大号文本（≥18pt 或 ≥14pt 加粗）与图形关键信息 ≥ 3:1。
- `success`/`warning`/`danger` 的前景文本同样须满足 AA；不能用「背景色 + 相同亮度前景」表达状态。

### 1.2 字阶

至少定义四档，并明确字号、行高、字重、用途：

- `title`：页面/大区块标题。
- `headline`：区块/卡片标题。
- `body`：正文与表单内容。
- `caption`：辅助说明、时间戳、次要信息。

要求：

- 支持 Dynamic Type / 系统字体缩放，字号不得写死为像素级且不可缩放。
- 大字号下布局不回缩、不截断，关键操作仍可触达。

### 1.3 间距、圆角、阴影

- 间距：4pt 网格，列出常用档位（如 4/8/12/16/24/32/48），避免任意奇数间距。
- 圆角：固定档位（如 0/8/12/16/full），同类组件使用同一档。
- 阴影：最多 2-3 档（低/中/高），只用于层级表达，禁止为了「好看」堆阴影。
- 命中目标与图标尺寸按第 4 节可访问性要求落地。

## 2. 组件四态清单

每个会异步加载、可能失败或被用户操作影响的组件，必须逐项定义：

- `empty`：无数据/首次空态，给说明文字和可选的下一步动作。
- `loading`：加载态，明确骨架或进度表现，不闪烁、不抖动。
- `error`：错误态，给出文本化原因和可操作恢复（重试/返回），不能只有图标或颜色。
- `success`：成功反馈，明确是瞬态提示还是持久状态。

表单控件额外定义 `disabled` 态：视觉可辨识且说明为何不可用，命中目标仍达标。

## 3. 每屏布局结构模板

`docs/ui-design.md` 中的每个屏幕至少写清三区：

- **导航区**：标题、返回/关闭、右上动作；位置与层级固定。
- **内容区**：主信息、列表/表单/图表，滚动行为，各状态在内容区如何呈现。
- **主操作区**：主次操作按钮、危险操作位置，键盘避让与安全区处理。

同时写清：进入条件、退出条件、用户主路径、空/错误态下的替代路径。

## 4. 可访问性

- VoiceOver / TalkBack：每个可交互元素有语义化 label，图标按钮有可读名称。
- 命中目标 ≥ 44×44pt（iOS）/ 48×48dp（Android），重要操作可更大。
- 错误、超限、状态变化必须文本化说明，不只靠颜色区分。
- 焦点顺序自然，弹层/键盘不遮挡关键操作。

## 5. 深浅色模式

- 同时给出 light 与 dark 两套令牌；语义色、对比度在两种模式下都达标。
- 禁止「暗色只是反色」：为暗色单独校准中性色阶与主色前景。
- 所有组件四态、屏幕三区在两种模式下逐一核对。

## 6. 产出检查表

`ui-designer` 完成 `docs/ui-design.md` 后自查：

- [ ] 令牌表齐全（色板/语义色/字阶/间距/圆角/阴影），每个语义色已标注对比度。
- [ ] 每个异步/可失败组件有 empty/loading/error/success 四态（表单含 disabled）。
- [ ] 每个屏幕有导航区/内容区/主操作区与空态/错误态替代路径。
- [ ] 可访问性条目落地到具体组件，而非空泛承诺。
- [ ] 深浅色模式两套令牌，语义状态不靠颜色单通道表达。
- [ ] 有设计稿时记录真实来源 URL 并忠实还原；无设计稿时按本指南产出，不伪造来源。
